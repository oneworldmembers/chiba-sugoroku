# 設計メモ

## 方針

- **ルールは `src/core` に閉じ込める。** すべて `(state, graph, ...) => newState` の純粋関数で、DOM・時間・`Math.random` に依存しない。
  UI やサーバー、テスト、AI 同士の自動対戦から同じコードを使える。
- **状態は JSON 1つ。** `GameState` に乱数状態（`rngState`）まで含むので、`JSON.stringify` すれば保存・共有・バグ報告ができる。
- **盤面はデータ。** マス・辺・物件はすべて `public/boards/*.json`。ルールのコードに地名は書かない。

## 盤面モデル

```
Board
 ├─ squares[]   町＝マス。id は "<市区町村コード>:<町名>"（例 "12203:国府台"）
 │    ├─ kind        property / plus / minus / card
 │    └─ properties  物件（物件マスのみ）
 ├─ edges[]     無向辺 [a, b]
 └─ startSquareId
```

- **ID に市区町村コードを含める理由**：「本町」「富士見」など同名の町が県内に多数あるため。
- **丁目はまとめる**：「国府台1〜6丁目」は「国府台」1マス。データ上の最小単位（町丁目）だと市街地が細かすぎ、山間部とのバランスが悪いため。
  `--no-merge-chome` で丁目単位の盤も作れる。

## 移動

- サイコロの合計 N に対して「ちょうど N 歩で止まれるマス」を列挙（`BoardGraph.reachable`）。
- 状態を `(現在マス, 直前マス)` として深さ N まで展開し、同じ状態は1つにまとめる。計算量は O(N × 辺数) なので数千マスでも問題ない。
- 直前のマスへの即時の引き返しは禁止（行き止まりでは許可）。

## 盤面生成の辺の張り方

| 入力 | 辺の作り方 |
| --- | --- |
| ポリゴンあり（e-Stat） | 境界を共有する町同士（2頂点以上共有） |
| 点のみ（手書き CSV・位置参照情報） | 各町から近い k 町（既定 3、15km 以内） |

どちらの場合も最後に**連結成分を最短距離でつなぐ**（離島・データ欠け・川で分断された町の救済）。

## 数千マス規模への課題（今後）

町名レベルで千葉県全域を作ると数千マスになり、サイコロ1回で進める距離が地図上ではごく短くなる。対策案：

1. **路線レイヤー**：`edges` に `{ kind: 'rail', line: 'JR総武線' }` を追加し、駅のある町同士は1歩で隣の駅へ進める。
   普段は道（町→町）、駅マスに止まったら電車で長距離、という2層構造。
2. **市区町村単位の目的地**：目的地を「市川市」などの単位にして、市内のどの物件マスでも到着扱い。
3. **ズームに応じた表示**：広域では市区町村単位の集約表示、拡大で町名マスを表示。
